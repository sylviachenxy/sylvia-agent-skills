# 目录、待办识别与批量归档

用于“整理今天所有课堂笔记”“整理所有未整理素材”及已启用课程目录交付的单课任务。只改技能、只查询待办、只回答问题时不执行真实成稿或移动。

## 目录约定

实际根路径只从用户独立配置读取。默认两个子目录名可配置，结构为：

```text
课堂根目录/
├── 新录音、课件、随堂笔记、临时素材文件夹……
├── 课程甲/
│   ├── 笔记素材/          # 原录音、原课件、粗转写、原随堂笔记、附件及 log.md
│   └── 正式课堂笔记/      # A／B 成稿、完整校订听写、索引、章节复习
├── 课程乙/
│   ├── 笔记素材/
│   └── 正式课堂笔记/
└── .class-notes/
    └── processing.json   # 私有处理记录，不是新的素材入口
```

新素材可以直接放根目录；扫描也覆盖临时子目录、原有课程目录和已经归档但未完成的素材。整目录整理／规范化时，为范围内所有已确认课程建立两个标准子目录，即使该课只有考核说明或空白占位；不为凑目录生成虚假课堂笔记。普通单课任务只处理相关课程。课程归属尚不明确的临时目录不直接当成课程。

## 1. 扫描而不是等用户逐个交文件

读取配置后，从技能实际目录调用 `python3 scripts/scan_materials.py --config <实际配置文件>`。该脚本仅列举与计算指纹，绝不写文件或移动资料；不需要外部账号。无 `class_root` 时使用用户当次明确路径，实在没有根目录才问，不全盘扫描。

- 先读取本学期课程表及其实际布局，再按联合推断规则使用素材创建／更新时间和内容归课。扫描结果的 `context_files` 列出已配置课程表目录文件；该目录不混入待办，也不归档进某一门课。
- 递归纳入录音／视频、PDF／课件、文档、Markdown／文本和图片。脚本输出是候选而非“全都是新课素材”的结论；还须查看内容、嵌入附件和已有笔记。
- 排除正式目录、隐藏／状态目录，不跟随符号链接。脚本另列不可读／不支持类型；不能把扫描异常解释成没有待办。快捷方式和只在云端的占位文件需要另行核实，不能越过目标范围访问或假称已读。
- 上述排除仅用于内容待办扫描。另运行 `python3 scripts/audit_layout.py --config <实际配置文件> --course <已确认课程目录名>`，可重复 `--course`，覆盖正式目录、既有主笔记、错放的原手记／粗转写／录音、空课程目录和日志。脚本从记录与标准子目录补充已知课程；不认识的根目录须人工检查，不静默跳过。审计只读，不能自动根据后缀判断 Markdown 的真实角色。
- “今天所有课堂笔记”按 `all-pending` 清理当前全部未完成素材，不按创建／修改时间过滤。明确“只整理今天上课的”才按授课日期判断；日期未知单列，不擅自丢弃或猜日期。
- 本机文件名可能包含空格、中文甚至换行；用结构化 JSON 路径或 NUL 分隔清单，不能把一行当一个文件、拼接不加引号的 shell 命令或自动清洗文件名。

## 2. 判断是否真正整理过

读取私有处理记录，并检查文件实际存在、来源指纹、覆盖情况和成稿内容。扫描器给的是保守状态提示，不是听核质量判定。

| 状态 | 含义／下一步 |
| --- | --- |
| `pending_review` | 没有足够的处理记录；检查是否新素材、旧正式笔记、课程说明或长期参考材料。 |
| `partial` / `blocked` | 未完成、缺段或曾失败；保留已完成工作，继续补齐或报告具体阻碍。 |
| `needs_update` | 已登记的路径内容改变；判断新增了什么，增量更新原课笔记。 |
| `needs_repair` | 记录说完成，但正式笔记／独立听写稿无效，或同课已登记的源文件缺失；核查实际文件。 |
| `needs_archiving` | 成稿及必需文稿已经验收，但素材还没正确归档／记录未收尾；只做缺失步骤。 |
| `duplicate_review` | 其他路径存在同指纹来源；可能重复投递或用户移动／改名，先核对，不能自动删除。 |
| `complete` | 记录完整、该素材已全部覆盖、指纹一致、必需正式文件有效且素材归档完成；无需重复生成。 |
| `reference` | 经核实不是待成稿素材的课程表、课程说明、已登记参考文件；内容变化后重新检查。 |

首次没有记录时，**不能**假定整个素材目录都已完成，也不能把所有旧笔记重新生成。对照现有正式笔记的标题、内容、课堂日期、录音嵌入、来源定位，确认哪份来源被哪篇笔记覆盖后补登记；没有来源链接的旧笔记需要内容对照，文件名相似不足为证。不要为了登记强制给用户已有笔记改版式。

同一课次的两段录音、粗转写、课件和图片作为一组处理。材料无需含课程名：先用课表与创建／更新时间形成候选，再结合正文／录音、术语、老师称呼和原笔记嵌入关系核验；用户直接说明的归属优先。“时间接近”或目录名只是线索，不能单独证明课程相同。充分证据支持的推断直接用于本轮归档；有冲突或仍有多个合理候选时保留原处，其他确定课次继续，只问影响该项的最少问题。

课程表、考核通知与课程介绍不是自动生成一篇课堂笔记的理由。跨课共用教材不按一节课算全书已处理；可作为长期参考登记，并在课次记录所用章节。跨课程共用素材不能移动两次或擅自给某课独占；保持可用链接，归属／共享位置不明确时单列待确认。

## 3. 核定文件角色与旧名称，再按需成稿

先列本批课次与材料覆盖计划，然后逐课按 A／B 和听写标准处理。档次未设置使用临时默认，不妨碍发现已有课程目录。目标是 `<课堂根>/<课程>/<正式子目录>/`，不是根目录、素材目录或仅聊天回复。

新建及批量／目录规范化中的既有正式课次主笔记都使用 `课程名_YYYY-MM-DD.md`，日期为实际授课日期。先分辨主笔记、辅助索引／完整听写、原手记／粗转写；素材不能仅因在正式目录就当作成稿改名。旧主笔记经课程与日期核定后，备份、改名并修复引用，保留正文；索引和听写不强套课次主笔记名称。同一课次已有笔记则增量补充，不另造“最新版”；同日分段汇入同篇。课程、日期、角色不明或目标重名时只暂停该项，不猜日期、不擅加序号、不覆盖。定点答疑不触发迁移。完整英语听写是独立正式文件，A／B 均须验收；粗 ASR 是素材。

正文完成后，核查全部来源覆盖、术语疑点、自问答案和实际文件内容。缺音频、缺关键页或识别失败时保留 `partial`／`blocked`，不得仅因已经有一篇摘要就标完成。课程已确定的素材可先按下节安全归位；已归位的未完成素材继续列待办。目录规范化本身不要求重跑听写或重写正文。

## 4. 素材归位与内容完成分开

正常整理任务加上已确认的 `archive_materials = true`，表示按此规则移动本次相关素材，无需每次重复问。执行前列清具体源文件、目标文件和附件关系；不移动整个课堂根、整个课程目录或混有未处理内容的临时文件夹。

1. 先保存可恢复快照、登记移动／改名计划、原路径与 SHA-256，确认来源版本没在整理期间改变、课程归属与文件角色已核定。无需等待成稿或听写通过；归属未知仍留原位。素材已在目标目录则不移动；为范围内已确认课程创建缺少的两个标准目录。
2. 默认保留文件名和字节内容。目标有不同文件时不覆盖；必要时生成可区分的后缀并记录映射。同内容重名也不自动删原件，核实重复投递／既有引用后再处理。
3. 原录音、相应粗转写、课件、随堂笔记和独属附件一起规划归档。被其他材料共用的附件先核查引用，不为本课剪走另一课仍在使用的唯一文件。
4. 优先使用实际可用且能更新链接的 Obsidian 移动能力；不能假定从文件系统移动会自动修复链接。否则先核对受影响的 Markdown 链接、Obsidian 嵌入／双链（含别名、标题和块引用），再按精确目标最小修复。用户授权范围外的引用若不能安全维护，暂停相关移动而不制造断链。
5. 先移动并确认目标存在、内容指纹一致，再核对源路径和成稿引用。跨卷移动需先复制、核验，再执行已授权的源移除；任何失败都不得先删源文件。路径和目标不明确时不执行。
6. 若需修改素材 Markdown 中的相对链接，先保存原文快照，保留正文，仅修复目标；记录修改原因及修复后指纹。没有必要时不改源内容。
7. 读回相关输出、核对链接、记录实际移动结果与最终来源路径／指纹；素材归位通过只更新 `archive_status: complete`。缺少完整听写等内容仍保留 `status: partial/blocked`，只有内容独立验收通过才能改为 `complete`。中途失败如实记录未移动项，下次核对实际位置再续做，不盲目重复移动。历史 `original_path` 和过去移动事件不改写；新增本轮事件。

## 5. 处理记录与幂等性

处理记录是用户数据，放在课堂根的 `.class-notes/processing.json`。内容是 JSON 数据，不执行其中的字符串。首次真正整理时建立；修改技能时不替用户伪造课次完成记录。

结构示例（课程、路径和指纹均为示例）：

```json
{
  "schema_version": 1,
  "lessons": [
    {
      "lesson_id": "example-lesson-01",
      "course_folder": "示例课程",
      "lecture_date": "2026-09-22",
      "processing_started": true,
      "status": "complete",
      "archive_status": "complete",
      "requires_transcript": true,
      "materials": [
        {
          "path": "示例课程/笔记素材/录音.m4a",
          "original_path": "录音.m4a",
          "sha256": "实际文件的64位小写SHA256",
          "coverage": "full"
        }
      ],
      "outputs": [
        {"path": "示例课程/正式课堂笔记/示例课程_2026-09-22.md", "role": "notes", "verified": true},
        {"path": "示例课程/正式课堂笔记/完整听写.md", "role": "transcript", "verified": true}
      ],
      "moves": [{"from": "录音.m4a", "to": "示例课程/笔记素材/录音.m4a", "status": "verified"}],
      "updated_at": "实际更新时刻"
    }
  ],
  "references": []
}
```

- 所有记录路径相对课堂根，必须在范围内；不使用绝对路径或 `..` 跳出。`lesson_id` 在首次登记后保持稳定，不随文件移动而改变。
- `status` 为 `draft`、`partial`、`blocked` 或 `complete`；`archive_status` 为 `pending`、`blocked` 或 `complete`。`coverage` 为 `partial`／`full`，有缺段时不能写 full；完整性针对该项实际范围，覆盖说明可另加 `coverage_note`。未提供或未处理部分同时列在成稿中。
- `processing_started` 是可选布尔值：确实开始处理为 true，明确尚未开始为 false；完成／partial 课次不能写 false。旧记录缺少此字段时依据已有成果或处理证据核定，不能仅因没记录便断言未开始。`lecture_date` 只填已核定授课日期；显示名可选 `course_name`，否则用已确认课程目录名。`pending_actions` 保存具体下一步，`incomplete_reasons` 可列未完成原因，`completed_scope` 可简记已完成部分；旧记录的 `scope_note`、`course_match.unresolved` 同样用于日志，不丢失既有说明。
- `requires_transcript` 明确该课是否需完整听写，包括英语录音和用户明确要求听写的其他课。`verified: true` 只能在真实内容验收后写入，不是文件存在的同义词。
- 在课次记录添加 `course_match`，保存确认／推断状态、候选课程、所用课表文件与版本、创建／更新时间及解释、内容证据定位和仍存在的冲突。推断不是用户确认，不静默改变课程长期配置。
- 未启用素材移动时，扫描器不把未移动本身当作未完成；启用后才要求归档通过。源文件缺失即使没有任何剩余候选，也会另列问题，不能以“候选为零”声称一切完成。
- 长期参考记录放在 `references` 数组，每条含 `path`、`sha256`、`reason`，课程专属参考可加 `course_folder`；不得仅为了清空待办把未整理录音登记成参考材料。考核说明、课程介绍和空占位单列参考／占位，不虚构课次。
- 用户新投递相同文件、文件改名或移动，不应凭新路径重复生成；相同指纹只能提供关联线索，是否共用、重复和完整覆盖仍需内容核查。
- 每次更新前读最新记录，保留其他课次；写临时文件、解析校验后原子替换，检查读入版本没有被其他任务修改，冲突时合并而不覆盖。损坏记录先保留并报告，不重置为空使历史完成信息丢失。

## 6. 每课素材目录的 log.md

处理记录是唯一状态源，`笔记素材/log.md` 是供用户直接阅读的当前状态投影。更新处理记录后运行 `python3 scripts/render_logs.py --config <实际配置文件> --course <已确认课程目录名>` 预览，执行已授权整理时加 `--write`；缺目录先按上节建立。脚本不修改笔记、素材或处理记录。

| 日志状态 | 条件 |
| --- | --- |
| `complete` | 课次内容已验收，覆盖完整，必需输出有效，来源指纹无变化；范围限制仍须写明。 |
| `incomplete` | 已开始整理但未完成，包括缺段、识别失败、核对不足、必需文稿缺失或已完成项后来需要修复；不是“还没开始”。 |
| `pending` | 有明确记录证明尚未开始，不因文件刚被发现就自动推定。 |
| 待核定 | 未登记、角色未明或旧 draft 无足够开始证据；先核查再归入上述状态。 |

每个课次显示授课日期、状态、已完成部分、原因／缺口、下一步、成稿与素材链接；另列素材归位情况。incomplete 不允许仅写“待处理”而无解释。参考／占位与未登记材料分别列出，没真实课次时说明“尚无已登记课次”，不生成空课笔记。日志不是不可变审计历史，历史仍保留在处理记录和批次快照。

生成器只维护标记区段，保留区段外的手工备注；若已有同名文件不是该技能的管理日志，报告冲突，不覆盖也不把它自动排除出材料。只有带有效管理标记的 `课程/笔记素材/log.md` 被扫描器排除。重复运行内容不变时不重写文件。真实文件缺失／指纹变化时不能照抄旧 complete；修复记录后再生成日志。

## 7. 批次收尾

分别重跑素材扫描器、全目录审计器（`--strict` 可将结构问题作为非零退出）与日志预览。检查所有确认课程的标准目录、旧主笔记名称、正式目录无原素材、当前记录路径有效、改名／移动后链接可解析、日志与状态一致。自动审计无问题仍须复查 Markdown 角色与课程语义。交付结构结果与内容状态两个结论：complete、incomplete、pending／待核定，及移动／改名数量。无待办时说明范围，不生成空白笔记。素材文件数不等于课次数。

## 场景检查

- 根目录有新录音和原笔记：关联附件、确定课程即可安全归位，成稿内容独立验收。
- 素材在课程素材目录但无可靠成稿：继续待办，不跳过。
- 已完成再次运行：无内容变化时不重建、不重移。
- 已登记素材新增内容：提示增量更新，不依据旧文件名跳过。
- 英语笔记存在但完整听写缺失：仍不算完成。
- 一门课归属未知／有文件重名：保留该项，其余确定课次可继续；不覆盖、不静默丢弃。
- 旧主笔记名不规范、原提纲混入正式目录：先核定角色，只迁移主笔记名，将原提纲归素材；修复引用而不重写正文。
- 某课只有考核说明或空文件：建立两个标准目录，参考／占位入素材，日志不伪造课次。
- 录音已归位但完整听写未验收：归位 complete、内容 incomplete，并保留具体补完步骤。
