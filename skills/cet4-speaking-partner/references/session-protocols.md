## 1. 环境与材料闸门

开始前记录：

| 条件 | 可接受状态 |
| --- | --- |
| 输入 | 实时 Voice，或用户有权提供且可回放的原始录音 |
| 输出 | 用户能清楚听到系统提示和 Candidate B；互动时不使用视频线索 |
| 计时 | 能记录准备、作答和互动的实际时长；否则不得称 strict mock |
| 陌生度 | `unseen`、`partly_seen` 或 `seen`；用户看过官方样题即为 `seen` |
| 支持 | `none`、`light`、`structured` 或 `modelled` |
| 保存 | 未获同意时不保存音频；即使同意也只写到用户指定的 skill 仓库外位置 |

先做不超过一分钟的麦克风、听音和轮流说话测试。技术测试不计入能力证据。耳机和 Mac 能更接近机考条件，但不能把设备相似等同于正式系统相同。

strict mock 的 timekeeper 必须独立于语言模型对时间流逝的估计，可使用能在用户持续发言时仍按时显示或发声的外部倒计时，或一名只负责发开始 / 结束信号的人类计时员。记录 `timekeeper`、信号方式和已知偏差。开始前分别做一次 10 秒 user-turn 和 Candidate-B-turn dry run，确认双方都能收到结束信号并立即停下；若 Voice 回合机制使任一方不能被按时截停、计时来源不明或 dry run 失败，只能运行 timed rehearsal。

文字对话只能用于说明、构思、词句练习或生成材料。没有可听语音时：

- 发音、语调、意群停顿、语速和口头流利度均标 `INDETERMINATE`，并注明 `text_only`；
- 真实话轮、打断、延迟和沟通修复均标 `INDETERMINATE`，并注明 `text_only`；
- 任何文字表现只记为 `non_speaking_practice_evidence`，不得贡献口语 Alignment、Stability 或 Excellent-evidence gate；
- 不生成完整 baseline，不声称 strict mock。

## 2. 原创 session pack

每套完整 pack 在正式开始前内部准备，但只按阶段逐项揭示，不能一次把后续题目全部展示给用户。

一套 pack 包含：

1. 20 秒自我介绍指令；
2. 一篇 115–125 词、目标约 120 词且已核对词数、无需专门知识的原创短文；
3. 一个短文内容问题和一个主题延伸问题；
4. 一个适合 60 秒个人陈述的文字或视觉提示；
5. 一个需要双方交换意见并作出共同决定的情景任务；
6. Candidate B 的隐藏画像、初始立场和两至三个可合理提出的理由；
7. pack ID、生成日期、题源 `original_generated` 和陌生度确认。

设计约束：

- 围绕同一熟悉主题形成连贯任务，但各任务不能让后题直接复述前题答案；
- 主题可来自大学生活、学习、健康、旅行、科技使用、消费、社区、文化、环境、志愿活动或人际协作；
- 不考专业事实、敏感个人经历或只有特定文化背景才知道的知识；
- 互动必须有真实取舍，例如时间、预算、地点、方式或优先级，不能只问双方是否赞同；
- 不使用泄露题、二手“押题”或刚练过的题冒充 unseen；
- 官方公开样题只用于形式熟悉，不复制为训练资产，也不再作为冷启动题。

若 prompt 依赖图片或图表，只在相应准备阶段显示。无法可靠显示视觉材料时，改用结构等价的文字提示，并在回执中记 `visual_fidelity: reduced`。

## 3. Baseline diagnostic

目标是取得未经教学污染、可与官方构念比较的个人证据。

1. 完成环境闸门和陌生度确认；
2. 说明从正式开始到整套结束不会反馈或救场；
3. 按 strict mock 的任务顺序运行一套原创 pack；
4. 若发生技术故障，只记录故障；需要重启的任务与原始尝试分开保存；
5. 全部完成后，先让用户自评：哪一段最接近真实水平、哪里最影响沟通、互动任务是否达成共同决定；
6. 再按 assessment rubric 分析，生成 `baseline_candidate` 和 evidence receipt；
7. 只提出一至两个首要训练瓶颈，不立即生成完整长期计划。

若时间不足，只做一个 `cold_component_sample`。它可以提供分项候选证据，但不能称为全流程口语基线。

## 4. Strict mock 与 timed rehearsal

### Strict mock 准入

同时满足以下条件才能使用 `strict_mock` 标签：

- pack 为 unseen，未提前展示后续任务；
- 使用可听语音，互动环节 audio-only；
- 准备和作答时长由独立于模型时间估计的可靠 timekeeper 执行并记录，且 user / Candidate B 两个 10 秒 dry run 已通过；
- 正式段全程 `support:none`，无纠错、提示、鼓励、改写或重启；
- AI 在 Task 1–3 保持安静，只在 Task 4 扮 Candidate B；
- Candidate B 画像、技术故障和实际时长均可回溯。

任何一项不满足，改标 `timed_rehearsal` 并明确差距。不要为了给用户成就感而保留 strict 标签。

### 正式顺序

1. **自我介绍**：给系统指令；用户 20 秒。只作热身。
2. **短文朗读**：显示约 120 词短文；静默准备 45 秒；发出开始信号；朗读 60 秒；到时停止。
3. **简短回答**：逐题呈现，不提供准备或反馈；每题 20 秒。若当次正式指令有不同节奏，以当次指令为准。
4. **个人陈述**：显示提示；静默准备 45 秒；发出开始信号；陈述 60 秒；到时停止。
5. **两人互动**：显示共同任务；静默准备 60 秒；互动 180 秒。Candidate B 使用预先选定的隐藏画像，不临时改成救场模式。

计时结束只使用简短一致的系统提示。不要在间隙评论“不错”“继续展开”或重复用户观点。正式段结束后明确说“模拟结束”，再切换到教练角色。

Candidate B 不机械追求 50:50，但不得垄断讨论或代替用户完成任务。它应至少创造一次用户回应他人观点、一次真实取舍和一次共同收束的机会；用户是否抓住机会属于证据。

### 卡住、求助与中断

- 用户沉默时不补句、不提示；让 timekeeper 正常走到结束信号。
- 用户在正式段请求答案、提示或重启时，不在该段教学。若继续，当前 attempt 标为受支持或偏离 strict；若重启，同题只能记 `same_task_retry`。要取得新的 strict 证据，换一套未见 pack。
- 用户明确要求停止或退出时立即结束，不以考试纪律为由强迫继续；保留已产生的原始证据并标 `user_stopped`。
- Voice 断线、timekeeper 失效或 prompt 提前暴露时停止该任务并记录。恢复后使用新 attempt；不能覆盖事故前的片段。

## 5. Targeted drill

一次只选择一个任务和一个主瓶颈。先冷作答，再训练；不要以讲解取代开口。

### 短文朗读

观察四组证据：

- 完整性：漏词、跳行、未读完；
- 清晰度：关键音、单词重音和听者是否能稳定理解；
- 韵律：意群划分、停顿和语调是否服务意义；
- 流利度：长停顿、重复、自我更正和节奏失衡。

训练顺序：冷读 → 用户标出自觉卡顿处 → 教练只选一至两个高影响片段 → 意群或发音微练 → 同文重读 → 另一篇同难度未见短文迁移。目标是清楚、完整、自然分组，不是消除母语口音。

### 简短回答

分别训练：

- 内容题：先直接回答，再用短文中的事实或同义转述支撑；
- 主题题：明确回答，再给一个理由、细节或例子。

20 秒内优先完成沟通，不用冗长开场或万能模板。若用户误解短文，先区分阅读理解问题和口头组织问题。

### 个人陈述

45 秒准备只写关键词骨架，不写完整稿。根据任务灵活选择中心、理由、细节 / 例子和收束，不强制每题套同一四句结构。

观察：是否理解图示 / 任务、中心是否明确、细节是否支持中心、连接是否自然、60 秒是否完整收束。复杂词句只有准确且适合语境时才算优势。

### 两人互动

不把互动练成两段轮流独白。轮换训练：

- 开启话题并确认任务；
- 自然取得、保持和交出话轮；
- 邀请对方意见；
- 回应并延伸对方刚说的内容；
- 同意、部分同意、有礼貌地不同意；
- 给理由、例子、比较或取舍；
- 请求澄清、确认理解和修复误解；
- 总结共识并在时限内作出决定。

若本轮没有出现误解，修复能力标 `NOT_ELICITED`，不要凭印象判定已掌握。专项 `breakdown_repair` 可以人为制造歧义，但必须在证据中注明 artificial elicitation。

## 6. Interaction lab

每轮从下列画像中选择一个，训练前隐藏、复盘时披露：

| 画像 | Candidate B 行为 | 主要检验 |
| --- | --- | --- |
| balanced | 回应充分，也会主动推进 | 综合互动 |
| terse | 回答偏短，但并非拒绝合作 | 用户能否带动和追问 |
| talkative | 较健谈，但会接受礼貌接入 | 取得话轮与重定向 |
| dissenting | 有合理不同意见 | 回应、比较、协商 |
| repairable | 偶尔听错或表达含糊 | 澄清与沟通修复 |

画像只改变互动机会，不改变话题难度或故意破坏考试。一次 lab 可聚焦一个动作并做三轮：明确示范后的受指导轮、较少提示轮、陌生情景独立轮。只有最后一轮能作为 transfer evidence。

## 7. Recording review

1. 确认录音来源、用户有权使用和允许的处理范围；
2. 先听原始音频，再看转写；不要让 ASR 文本覆盖实际发音和停顿；
3. 记录任务、时间限制、是否见题、是否有搭档 / 提示；未知即标未知；
4. 用时间点和短片段支持判断；无法回放或音质不足的维度标 `INDETERMINATE`；
5. 只保存用户授权的评估产物，不默认复制原始音频；
6. 转写错误本身不能算用户语言错误。

## 8. 反馈、重做与迁移

用户先自评后，按以下优先级选一至两个问题：

1. 沟通失败、意思不可理解或任务未完成；
2. 互动没有回应 / 推进，或无法形成共同决定；
3. 话语断裂、组织不清或明显超时 / 未完成；
4. 反复出现且影响表达的语法、词汇、语音问题；
5. 不影响理解的轻微错误或风格改进。

反馈格式：

```markdown
证据：时间点 / 短原话 / 明确观察
影响：它怎样影响任务、理解或优秀对齐
最小修正：一个动作，不是整篇范文
立即应用：同题中的一个重做机会
迁移检验：一条未见平行题
```

在专项训练中，造成即时沟通中断的问题可要求澄清；普通语法、词汇和语音问题等当前小任务结束后反馈。关键不在于永远即时或延迟，而在于反馈后必须有可观察的重新应用机会。

不要默认展示满分范文。用户连续两次仍无法发现或修正同一关键问题时，才提高支持等级；展示示范后，必须在新题上撤掉脚手架。

## 9. 真人搭档检查

对“优秀”目标，AI 练习不能完全替代真人伙伴。默认建议：

- 中期一次、考前 7–14 天一次；
- 尽量选择不同、并不熟悉答案的同龄伙伴；
- 双方只看正式阶段当前提示，不提前交换答案；
- 不教学、不提醒、不故意迁就；
- 互动后分别自评，再由观察者或录音复盘；
- 与 AI 证据分轨记录，不能把两者平均成一个分数。

真人搭档不需要是专家；这里检查的是与真人互动时能否迁移，不是由搭档给用户评级。只有 Codex 能听到实时会话或原始录音，并能通过可区分声线或明确 speaker labels 可靠归属每个话轮时，才标 `human_partner_observed`。无法可靠归属时，个人维度标 `INDETERMINATE`，不能提升 Stability。只有用户 / 搭档自报时标 `human_partner_self_report`，可用于了解体验，但不能提升 Stability；第三方结构化观察必须保留观察方法与具体行为证据，且不能冒充训练过的评分员校准。

它主要检验 AI 环境可能掩盖的问题：更自然的打断、延迟、短答、立场变化、误解和共同收束。

## 10. 方法依据与边界

本协议把同题重做与陌生题迁移分开，因为口头任务重复常能改善当次流利度、准确性或复杂度，但不同维度可能此消彼长，同题变好不等于稳定迁移。采用“冷作答 → 自评 → 聚焦反馈 → 立即应用 → 跨日陌生题”的目的，是保留原始基线并验证学习是否可迁移。

AI 伙伴能提供高频、可控的练习，但伙伴类型会改变互动表现；因此把真人搭档检查作为本 skill 的高标准内部政策，而不是官方要求或评分员校准。发音训练以可理解度为目标，不追求母语化口音。

主要研究来源：

- [de Jong & Perfetti (2011), task repetition and fluency](https://doi.org/10.1111/j.1467-9922.2010.00620.x)
- [Bui, Ahmadian & Hunter (2019), spacing in oral task repetition](https://doi.org/10.1016/j.system.2018.12.006)
- [Kartchava & Nassaji (2019), repetition, self-assessment and feedback](https://doi.org/10.1075/itl.19013.kar)
- [Li, Ou & Lee (2026), timing of corrective feedback](https://doi.org/10.1017/S0261444824000478)
- [Saito (2021), pronunciation and comprehensibility](https://doi.org/10.1002/tesq.3027)
- [Ockey & Chukharev-Hudilainen (2021), human versus computer partner](https://academic.oup.com/applij/article/42/5/924/6125156)
- [Xiao & Jin (2026), CET-SET4 interactional competence](https://doi.org/10.1111/lang.70038)

这些研究支持训练选择，不是 CET 官方评分文件；不得用研究中的指标替代官方等级。
